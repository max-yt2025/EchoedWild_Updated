# Contributing to EchoedWild

Thank you for your interest in contributing to EchoedWild! 🐾

EchoedWild is a wildlife education platform focused on making information about animals, conservation, and biodiversity accessible to students, educators, developers, and wildlife enthusiasts.

Whether you're an experienced developer or making your first GitHub contribution, you're welcome here.

## 🤝 Who Can Contribute?

Anyone who wants to help improve EchoedWild can contribute, as long as they follow this project's guidelines and GitHub's Terms of Service.

You do not need to be an expert developer. Contributions can include code, documentation, accessibility improvements, research, design suggestions, bug reports, and more.

## 👥 Joining the EchoedWild Developer & Tester Team

Some contributors may be invited to officially join the **EchoedWild Developer & Tester Team**.

Team members who are accepted may receive an invitation to join the **EchoedWild GitHub organization/team** so they can collaborate more directly on the project.

Being part of the team may provide access to:

* 🧑‍💻 Collaborative development
* 🧪 Testing new EchoedWild features
* 🐛 Working on issues and bug fixes
* 💡 Discussing upcoming features
* 🔎 Reviewing changes
* 🌐 Helping improve the website
* 📦 Working with Pull Requests
* 🤝 Collaborating with other EchoedWild contributors

### How Team Invitations Work

Contributors can demonstrate their interest and reliability by participating in the project through issues, Pull Requests, testing, documentation, research, or other approved contributions.

The EchoedWild project team may then invite selected contributors to join the appropriate GitHub team or organization.

**A GitHub team invitation is not automatic simply because someone contributes.** Team access is provided at the discretion of the EchoedWild project maintainers.

Team members are expected to follow:

* This contributing guide
* The EchoedWild Code of Conduct
* GitHub's Terms of Service
* The project's security policies
* Any additional guidelines provided by the EchoedWild maintainers

Never share GitHub passwords, authentication codes, personal access tokens, or other account credentials with another contributor.

## 🐛 Issues

Before opening an issue, please check whether someone has already reported the same problem.

When reporting a bug, include:

* What happened
* What you expected to happen
* Steps to reproduce the problem
* Browser and device information when relevant
* Screenshots or other useful information when appropriate

Please do not include passwords, API keys, authentication tokens, or other private information in an issue.

## 💻 Setting Up EchoedWild

To work on EchoedWild locally:

1. Fork the repository on GitHub.
2. Clone your fork to your computer.
3. Open the project in your preferred code editor.
4. Create a separate branch for your changes.
5. Make and test your changes locally.
6. Commit your changes.
7. Push your branch to your fork.
8. Open a Pull Request.

Example:

```bash
git clone https://github.com/YOUR-USERNAME/EchoedWild_Updated.git
cd EchoedWild_Updated
git checkout -b feature/my-change
```

Replace `YOUR-USERNAME` with your GitHub username.

## 🌿 Making Changes

Please keep changes focused.

For example, if you're fixing a navigation bug, avoid changing unrelated parts of the website in the same Pull Request.

Before submitting your changes:

* Check your HTML, CSS, and JavaScript for errors.
* Test the affected pages.
* Check both desktop and mobile layouts when relevant.
* Make sure links work.
* Check that images load correctly.
* Avoid introducing unnecessary dependencies.
* Keep accessibility in mind.

## 📦 Pull Requests

Pull Requests (PRs) are how proposed changes are submitted to EchoedWild.

A good Pull Request should:

* Have a clear title.
* Explain what was changed.
* Explain why the change was needed.
* Include testing information.
* Reference an issue when applicable.
* Keep unrelated changes out of the PR.

Pull Requests may be reviewed, requested for changes, approved, or declined.

Please be respectful during the review process. Code review is intended to improve the project, not criticize contributors.

## 🎨 Code & Design Guidelines

### HTML

* Use semantic HTML where possible.
* Keep markup organized and readable.
* Include appropriate `alt` text for meaningful images.
* Avoid unnecessary inline styles.

### CSS

* Keep styles organized.
* Reuse existing classes and patterns when practical.
* Make designs responsive.
* Avoid breaking existing layouts.

### JavaScript

* Keep JavaScript readable and maintainable.
* Use clear variable and function names.
* Avoid unnecessary dependencies.
* Test interactive features before submitting them.

### UI/UX

EchoedWild aims to provide a professional, educational, accessible experience.

When changing the interface, consider:

* Mobile users
* Keyboard navigation
* Readability
* Accessibility
* Page performance
* Consistency with the existing EchoedWild design

## 🧪 Testing

Please test your changes before opening a Pull Request.

Depending on your contribution, this may include:

* Opening affected pages locally.
* Testing links and navigation.
* Testing forms and interactive features.
* Checking browser console errors.
* Testing responsive layouts.
* Checking accessibility.
* Testing on more than one browser when practical.

## 🔐 Security

Never commit sensitive information to this repository.

This includes:

* API keys
* API tokens
* Passwords
* Authentication credentials
* Cloudflare API tokens
* Resend API keys
* Supabase service-role keys
* Private keys
* Other secrets

If you accidentally expose a secret, **do not simply delete it from the file and assume it is safe**. The secret may still exist in Git history.

Revoke or rotate the exposed credential and report the issue privately.

For security vulnerabilities, see [`SECURITY.md`](SECURITY.md).

## 📝 Commit Guidelines

Please use clear commit messages that describe what you changed.

Examples:

```text
Fix mobile navigation
Update animal search UI
Improve accessibility labels
Add conservation resources
Fix broken footer links
Update documentation
```

Avoid commit messages such as:

```text
stuff
changes
idk
update
asdf
```

Small, descriptive commits make the project easier to maintain.

## 🌎 Community Expectations

Please be respectful toward other contributors.

We welcome contributors with different experience levels and backgrounds.

Do not:

* Harass or insult contributors.
* Discriminate against others.
* Spam Pull Requests or issues.
* Intentionally disrupt the project.
* Submit malicious code.
* Submit work that you do not have permission to use.
* Share another person's private information.

Please see [`CODE_OF_CONDUCT.md`](CODE_OF_CONDUCT.md) for the project's full community standards.
